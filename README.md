# Enter 换行 / Enter newline

把 DSH 输入框的发送键从 Enter 改成 Ctrl/Cmd+Enter，并允许在设置里重新分配三个按键：插入换行、插话发送、排队发送。

## 安装

```sh
# npm
dsh plugin --profile web add dsh-enter-newline

# GitHub 源码（pnpm 第一次会要求放行构建脚本，按提示重试；建议钉定 commit）
dsh plugin --profile web add github:Librorum545/Enter_Newline#<commit>
```

桌面端的 profile 由应用自己的插件管理器管理：在 **设置 → 插件** 的安装入口填入 `dsh-enter-newline`。装好后刷新页面，桌面端需要重启窗口。

要求 DSH `>=0.2.2-rc.5 <0.3.0-0`，见 `package.json` 的 `engines.dsh`。

## 默认行为

| 按键 | 默认动作 | 空闲会话 | 智能体运行中 |
|---|---|---|---|
| Enter | 插入换行 | 插入换行 | 插入换行 |
| Ctrl/Cmd+Enter | 插话发送 | 发送 | 插话进入当前回合 |
| Shift+Enter | 排队发送 | 发送 | 排进队列，本轮结束后再发 |

三个按键各自可以从「插入换行 / 插话发送 / 排队发送」里任选，所以上表只是默认值；改过之后以设置页保存的映射为准。发送类动作只在智能体运行时有区别：空闲时「插话」和「排队」都只是正常发送。

补全菜单（`/` 命令、`@` 引用）打开时，Enter 仍然交给菜单选中候选项；输入法组合中的 Enter 交给输入法。这两种情况下插件不介入，当前映射暂时不生效。

## 设置页

插件在 **设置** 里注册一页「Enter 换行」（排在「通用设置」之后）：三行分别对应 Enter、Ctrl/Cmd+Enter、Shift+Enter，右侧下拉框选择该按键的动作，底部是「放弃」和「保存」。

保存时检查两项，任一项不满足就驳回并提示：

- 没有任何按键负责「插入换行」：草稿将无法换行。
- 三个按键全是「插入换行」：将无法用键盘发送。

检查只在点「保存」时进行，中途怎么改都可以；「放弃」把三个下拉恢复到上次保存的值。

「保存」按钮只在配置与已保存映射不同时才可点：有改动时是深色的品牌色按钮；没改动、或改回与原来一致时变灰且禁用。保存成功或点「放弃」后，按钮回到灰色。

映射保存在浏览器本地（`localStorage` 键 `composer-enter-newline:bindings:v1`）：它描述的是"这台机器上这几个键怎么按"，不进入共享的设置文档。

DSH 内置的「繁忙时的发送行为」说明文字（`设置 → 通用`）属于 `ui-conversation`，不是本插件的地盘：Client locale 注册表对每个命名空间与语言只允许一个所有者，重复注册会直接抛错，所以插件不能改写那段文案，只能自己提供一页说明与配置。

## 实现方式

浏览器端插件在 window 捕获阶段接管 Enter 的三种组合，按保存的映射重放成 composer 已经认识的手势：

- 插入换行 → 重放 Shift+Enter 的 keydown，由 composer 的 Lexical 键位在同一次按键里插入换行节点。
- 插话发送 / 排队发送 → 重放普通 Enter 或 Ctrl+Enter 的 keydown。composer 的 `resolveSubmitMode` 规定：普通 Enter 走「繁忙时的发送行为」，Ctrl/Cmd+Enter 走相反的那个；插件读取该设置的当前值（`ui-conversation` 命名空间里的 `busyEnter`），据此挑选手势，所以「插话/排队」的含义不受用户改设置影响。

每次按键只派发这一个事件：再补发一次 `beforeinput` 会插入第二个换行，因为 Lexical 的 DOM 提交发生在派发返回之后。插件不直接调用发送按钮，也不读写草稿内容；附件、引用、命令 chip、撤销历史、输入法组合态都沿用原代码。

设置页走 Client 的 `settings.section` 与 `settings.section.icon` 槽位：分区页由插件注册（`order: 5`，紧跟「通用设置」），导航图标与分区同 id，文案注册在插件自己的 locale 命名空间里，切换语言时整页跟随。

## 边界

- 输入法组合中的 Enter 不拦截，由输入法选中候选词。
- 草稿只读（发送中、会话不可用）时不拦截。
- 补全菜单打开时 Enter 归菜单，三种手势都暂时不生效。
- 同一页面内的所有 composer（含右侧边栏的子智能体会话）都生效。
- 只改前端按键映射，不改变 Host 的投递语义。

## 关闭与移除

在 **插件** 面板禁用或移除本插件即可恢复原来的 Enter 发送行为。禁用会立刻撤掉按键拦截和设置页；重新启用即可加载新版本而不必重启整个桌面端（Host 在插件条目启动时重新读取 `client.js`）。

## 已知限制

- 依赖 composer 的 `data-composer-input` 标记与补全菜单的 `role="listbox"`；DSH 改版后需要同步更新。
- 仅适用于 Chromium 内核（桌面端、Chrome/Edge 打开的 Web 页面）；Safari/WebKit 把换行交给原生事件，这里没有覆盖。
- 「插话/排队」依赖读取 `ui-conversation` 的 `busyEnter`；读不到时按 `queue` 处理。
- 会话不支持插话时，「插话发送」由 composer 自行退化为排队，与 DSH 原生行为一致。
- 输入框为空、且队列里已有消息时，走 Ctrl/Cmd 通道的动作按 DSH 原生语义变成「插话全部排队消息」（空草稿本来也发不出内容）。
- 按键映射存在浏览器本地，不同浏览器/不同机器需要各自设置。
- 内置的「繁忙时的发送行为」说明文字由 `ui-conversation` 拥有，插件无法替换（同一 locale 命名空间与语言只允许一个所有者）；想改那段文字只能走 DSH 上游。
- 插件在 DSH 启动时加载；安装或修改后需要重启桌面端，或在 **插件** 面板禁用后重新启用。

## 测试

`npm test` 用最小的 React 与 window 打桩直接运行 `client.js`：检查默认映射、已保存映射、`busyEnter` 变化时手势的翻转、输入法与修饰键边界、设置页注册参数与三个下拉、保存校验与放弃恢复、保存按钮的脏/净状态（颜色与禁用），以及中英文案键是否齐全。
